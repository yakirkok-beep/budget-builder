# בונה תקציב - מחלקת ההדרכה, תנועת עזרא

**האתר:** https://yakirkok-beep.github.io/budget-builder/

אתר סטטי (Vite + React + TypeScript) שבונה את התקציב השנתי של מחלקת ההדרכה מתוך פרמטרים של כל מפעל.
מקור האמת לדרישות: [CLAUDE.md](CLAUDE.md). מקור האמת ללוגיקה: אב הטיפוס (פרטי, ב-`private/reference/`).

> **האתר וה-repo ציבוריים, ולכן בלי מספרים אמיתיים.** האפליקציה עולה עם תבנית לדוגמה (אותו מבנה, מספרים בדויים).
> את התבנית האמיתית של המחלקה טוענים מקובץ JSON פרטי במסך "שמירה וגיבוי". פרטים ב-CLAUDE.md סעיף 16.

## הרצה מקומית

צריך Node.js 20 ומעלה.

```bash
npm install
npm run dev
```

## בדיקות

`npm test` מריץ את בדיקות הקבלה מסעיף 13: סכומי כל התקציב, כל מפעל וכל קטגוריה, שלושת התרחישים,
מנוע הנוסחאות, שינוי שם, טבלת פריוריטי ו-round trip של JSON. בנוסף: פעולות העריכה, וה-store מול
IndexedDB מדומה (fake-indexeddb): הפעלה ראשונה, שמירה ורענון, השהיית 1.5 שניות, כשל שמירה, ריבוי תקציבים וייבוא.

בנוסף, בשלב 1 הורצה השוואה חד-פעמית מול הקוד של אב הטיפוס: התוצאות זהות בדיוק (כל שורה, קטגוריה,
פרמטר ושורת פריוריטי) על ה-seed ועל 300 תרחישים אקראיים.

## ממשק

עיצוב: השפה של אתר הצוות (Rubik, כחול עזרא, כותרות עם שורה בכתב יד וקו מכחול זהב, תפריט צד עם סמלי הערכה של הפורטל).

- **ריכוז:** טבלת מפעלים עם תיבת "נכלל בתקציב", השוואה ל-2026, גרף הוצאות מול הכנסות, ורשימת "לבדיקה" לפי מפעל.
- **מפעל:** פרמטרים (שינוי שם מעדכן את כל הנוסחאות), הכנסות, שורות הוצאה לפי קטגוריה עם סכום ביניים,
  וצד דביק עם סעיפי פריוריטי, סיכום עם קו כפול ובעיות. עזרה לנוסחאות: לחיצה על שם מכניסה אותו לשדה האחרון.
- חישוב מחדש בכל הקשה, בלי לאבד פוקוס ובלי קפיצה בגלילה. Enter מאשר שדה, Escape מבטל שינוי שם.
- **בטל / בצע שוב:** Ctrl+Z ו-Ctrl+Y (או Ctrl+Shift+Z), וכפתורים בראש העמוד. עד 100 צעדים לכל תקציב.
  הקלדה רצופה באותו שדה היא צעד אחד. אפשר לבטל גם מחיקת מפעל, שינוי שם ואיפוס לתבנית. עובד גם במקלדת בעברית.
- **השלמה אוטומטית** בשדה נוסחה במסך המפעל: מתחילים להקליד שם ומופיעה רשימה (פרמטרים עם הערך שלהם,
  פרמטרים כלליים, מחירון, פונקציות). חיצים לבחירה, Enter או Tab לאישור, Escape לסגירה.
- **פרמטרים ומחירון:** פרמטרים כלליים (רמת שכר כבחירה), מחירון עם הוספה ומחיקה. ערך לא תקין מסומן ליד השדה ובנקודה על הלשונית.
- **שכר מנחים:** שעות, שכר מינימום מחושב (שעות × שכר מינימום), 4 רמות. העמודה של הרמה שבשימוש מודגשת.
- **טבלת פריוריטי:** שורה לכל קטגוריה והכנסה, פריסה ל-12 תקופות, "חסר קוד" ו"לקבוע" מסומנים, שורות סיכום,
  וכפתור העתקה (TSV, שני מקומות עשרוניים, בלי פסיקים) להדבקה ב-Excel.
- מחיקות (מפעל, קטגוריה עם שורות, פריט מחירון או שורת שכר שמשמשים בנוסחאות) שואלות בדיאלוג בתוך העמוד.
- מתחת ל-1250px הכל בעמודה אחת; עובד גם בטלפון בלי גלילה הצידה. מצב כהה לפי הגדרות המערכת.

## שינויים קטנים לעומת אב הטיפוס

החישוב עצמו זהה. השינויים נוגעים רק למקרי קצה ולהודעות:

- **בעיות:** הודעה אחת לכל סוג בעיה בכל מפעל (כמו בסעיף 7), במקום הודעה לכל שורה.
- **שינוי שם** של פרמטר או פריט מחירון לא נוגע בטקסט בתוך מירכאות, למשל `שכר("סמינריון")` נשאר כמו שהוא.
  שינוי לשם שכבר קיים (פרמטר, פריט מחירון, קטגוריה, שורת שכר) נחסם.
- **שינוי שם של שורה בטבלת השכר** מעדכן את כל הנוסחאות `שכר("...")` (באב הטיפוס הן נשברו). נוסף גם ל-CLAUDE.md.
- **ערכים בטבלת השכר** מחושבים כמו שאר הערכים (אפשר גם נוסחה קבועה כמו `=1200*1.1`), וערך לא תקין מסומן ליד השדה.
- **ערך טקסט** כמו `12abc` הוא שגיאה (באב הטיפוס הוא נקרא כ-12).
- **פונקציות** בודקות את מספר הערכים (`למעלה()` מחזירה שגיאה ברורה).
- **עלות לנפש** ריקה כשמספר המשתתפים 0 (במקום אינסוף).
- **מחיקת הפרמטר** שמשמש כ"משתתפים" מנקה גם את הבחירה שלו.
- **מעבר בין תקציבים** נחסם אם השינויים בתקציב הפתוח לא נשמרו (באב הטיפוס הם היו הולכים לאיבוד).

## שמירה

- הכל נשמר אוטומטית ב-IndexedDB של הדפדפן, 1.5 שניות אחרי השינוי האחרון, ושוב כשהלשונית נסגרת או מוסתרת.
- מחוון מצב: "יש שינויים", "שומר", "נשמר" (או "השמירה נכשלה" עם הסבר).
- בהפעלה הראשונה נטענת התבנית לדוגמה ונשמרת כתקציב הראשון. את התבנית האמיתית טוענים מ-JSON.
- כמה תקציבים במקביל (טיוטה, תרחיש חיסכון...): בחירה מהרשימה בראש העמוד, "תקציב חדש" מהתבנית או כעותק,
  ובמסך "שמירה וגיבוי" גם מחיקה, שינוי שם ואיפוס לתבנית. מעבר בין תקציבים שומר קודם את הפתוח.
- אחרי רענון נפתח התקציב האחרון שהיה פתוח.
- אם IndexedDB לא זמין (למשל בחלק ממצבי הגלישה בסתר), הכלי עובד, אבל מציג הודעה שהשינויים לא יישמרו אחרי רענון.
- כפתור "בקשת שמירה קבועה" (`navigator.storage.persist()`) מבקש מהדפדפן לא למחוק את הנתונים כשחסר מקום.

## גיבוי והעברה

- **ייצוא JSON** (מסך "שמירה וגיבוי"): כל התקציב הפתוח כמו שהוא, כולל נוסחאות.
- **טעינת JSON**: הקובץ נבדק (צריך `events` ו-`globals`), עובר `migrate`, ונפתח כתקציב חדש בשם "... (ייבוא)". לא דורס כלום.
  כך מעבירים תקציב למחשב אחר.
- **ייצוא ל-Excel** (בראש העמוד): קובץ `.xlsx` מימין לשמאל עם הלשוניות ריכוז, טבלת פריוריטי, לשונית לכל מפעל,
  פרמטרים ומחירון, שכר מנחים. הסכומים כערכים מחושבים, וליד כל שדה עם נוסחה טקסט הנוסחה בעמודה נפרדת.
  כותרות צבועות, פורמט `#,##0`, שורות סה"כ מודגשות עם קו כפול. (נוסחאות חיות בתוך Excel: שלב 7.)

## עבודה בלי אינטרנט (PWA)

אחרי ביקור ראשון באתר המפורסם, הכלי נטען ועובד גם בלי חיבור (כולל ייצוא ל-Excel). אפשר גם להתקין אותו
כאפליקציה מהדפדפן (בכרום: סמל ההתקנה בשורת הכתובת). גרסה חדשה מתעדכנת אוטומטית בביקור הבא.
הסמל ב-`public/icons/` הוא זמני (₪ על רקע התנועה). אפשר להחליף בלוגו: אותם שמות קבצים ואותם גדלים.

## פריסה ל-GitHub Pages

הקובץ `.github/workflows/deploy.yml` מריץ lint, בדיקות יחידה ובדיקות Playwright, בונה, ומפרסם.
הבנייה משתמשת בנתיבים יחסיים, כך שהאתר עובד בכל שם repo.

פעם אחת:

1. יוצרים repo ב-GitHub (ב-GitHub Pages בחינם ה-repo צריך להיות ציבורי; repo פרטי דורש מנוי בתשלום).
2. מחברים ודוחפים:

   ```bash
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```

3. ב-repo: Settings > Pages > Source: **GitHub Actions**.

מכאן כל דחיפה ל-`main` מפרסמת מחדש, אם כל הבדיקות עוברות. הכתובת: `https://<user>.github.io/<repo>/`.
הנתונים לא עולים ל-GitHub: כל משתמש שומר את התקציבים שלו בדפדפן שלו.
